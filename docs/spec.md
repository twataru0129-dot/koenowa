# 「こえのわ」Webアプリ開発指示書（Claude Code用／統合版 v1.0）

あなたは、AAC（補助代替コミュニケーション）、iPhone向けPWA、アクセシビリティ、自然な日本語の音声読み上げに詳しいエンジニア兼UI/UXデザイナーです。

以下の要件を満たす、**実際に利用できる文字盤コミュニケーション支援アプリ「こえのわ」**を実装してください。デザインのみのモックアップで終わらず、入力・編集・読み上げ・保存・PWAまで動作するものを目指します。判断できる点は自律的に進め、完了時に検証結果と未検証事項を区別して報告してください。

---

## 0. まず実行すること／作業上の制約

1. 作業ディレクトリに既存コードがある場合、**変更前に**Git状態、README、package.json、画面・音声・PWA関連コード、テスト、公開設定を調べて、影響範囲を簡潔に整理する。
2. 新規プロジェクトの場合は、React + TypeScript + Viteを基本候補とし、依存関係を必要最小限にして保守しやすく構成する。すでに適切な技術基盤があれば不要な全面移行をしない。
3. 既存の機能・設定・データを壊さない。可能なら作業用ブランチを利用する。
4. **mainへの直接変更、既存データの破壊的操作、マージ、本番デプロイ、一般公開はユーザーの明確な許可を得るまで実施しない。** GitHubへのpushやPR作成が必要なら、事前に作業内容を提示する。
5. 外部の有料API、クラウドDB、ログイン、AI音声生成サービス、分析SDKは導入しない。
6. 開発途中で実機依存の問題が見つかっても、未検証なのに「確認済み」としない。代替案を示す。

## 1. アプリの目的と優先順位

- **アプリ名：こえのわ**
- 目的：発話によるコミュニケーションは難しいが、ひらがなをある程度理解している利用者が、文字を一文字ずつタップして文章を作り、音声で相手に伝える。
- **主な端末：iPhone**。通常は横向きで使う。縦向きでも全ての文字を同じ配置で表示する。
- iPadにも対応（縦・横）。PCでの基本操作も可能にする。
- 家庭・学校・外出先で使うため、**ネット接続なしでの利用**を重視する。
- 子ども向けの過度な装飾は不要。高校生・成人が使っても違和感のない、温かみのあるデザインにする。

優先順位：**①正確に文字を選べる → ②確実に相手へ発声できる → ③文章を見やすく・直しやすくする → ④見た目の洗練**。

## 3. 全体の画面構成

### メインの「こえのわ」画面

上から順に、次の要素を持つ。

1. **上部：入力文章エリア**（大きな黒文字・白系背景・高コントラスト）
2. **操作ボタン**：発声（最も目立つ）、読み上げ停止、1文字削除、全文削除、元に戻す、よく使う言葉
3. **五十音文字盤**（その端末の向きで全マスを一画面に表示）
4. **現在のページ表示とページ切り替え手段**（スワイプ＋左右ボタン等）

文字盤は次の**3ページだけ**を基本とする。

- ページ1：清音
- ページ2：濁音・半濁音
- ページ3：小文字・記号

**左右スワイプで切り替える。** 左へスワイプで次、右へスワイプで前。切り替え中も入力文章とカーソルは保持。現ページを見失わないよう番号・ページ名・位置インジケーターを表示。スワイプが難しい場合のために、タップで切り替える操作も用意する。

文字キーの単純なタップでは**文字を入力するだけ**。**一文字ごとの音声再生・効果音はしない。**

## 4. 確定文字配列（厳守）

### 4-1. 清音ページ

**10列×5段を固定配置**。右端が「あ行」、左端が「わ行」。上から下へ母音順。左から右へ見た各段は以下のとおり。

```text
わ   ら   や   ま   は   な   た   さ   か   あ
を   り   □   み   ひ   に   ち   し   き   い
ん   る   ゆ   む   ふ   ぬ   つ   す   く   う
、   れ   □   め   へ   ね   て   せ   け   え
。   ろ   よ   も   ほ   の   と   そ   こ   お
```

- `□` は**空欄（ボタン無効）**。マスを詰めたり左寄せしたりしない。
- 清音ページに「が」「ざ」「だ」「ば」「ぱ」等を混ぜない。
- 「、」「。」は上記の左端の位置に配置する。
- 画面の向きや端末が変わっても、列順・行順・空欄位置を変えない。
- キーは明るい背景＋青系文字。ボタンの押下が分かる短い視覚フィードバックを与える。

### 4-2. 濁音・半濁音ページ

**5列×5段**。右から「が行・ざ行・だ行・ば行・ぱ行」。つまり左から右は「ぱ・ば・だ・ざ・が」。

```text
ぱ   ば   だ   ざ   が
ぴ   び   ぢ   じ   ぎ
ぷ   ぶ   づ   ず   ぐ
ぺ   べ   で   ぜ   げ
ぽ   ぼ   ど   ぞ   ご
```

- **濁点や半濁点を後付けする入力方式にしない。** 一文字を直接押す。
- 「ば行」「ぱ行」は**同じページ**に両方表示する。
- 清音ページより列数が少ないため、自然な範囲でキーを大きくしてよい。
- 配列は毎回固定する。

### 4-3. 小文字・記号ページ

直接入力できる小文字：

`ぁ ぃ ぅ ぇ ぉ ゃ ゅ ょ っ ゎ`

記号：

`ー 、 。 ？ ！ 「 」 （ ） ・`

操作キー：`空白`、`改行`

- すべて同じページに収める。配列は実装時に読みやすい固定位置を設計し、その後は毎回変えない。
- `き` → `ょ` → `う` で `きょう`、`ぱ` など濁音ページとの行き来も問題なく行えること。
- `空白` は半角／全角のいずれかを一貫して採用し、見た目と保存・発声が破綻しないようにする（標準は半角スペースでよい）。
- `改行` は文章に改行を挿入し、読み上げ時には自然な区切りとして解釈させる。

## 5. iPhone優先のレスポンシブ要件

### iPhone横画面【最優先】

- 記事本文のスクロールなしで、文章表示・主要操作・現在の文字盤の全マスを基本的に見せる。
- 清音10×5、濁音5×5、小文字と記号の**すべてのキーを省略せず**表示する。
- 実際のiPhoneの画面高さ、Safariのツールバー、Safe Areaを考慮する。
- 装飾・ヘッダーは必要最小限。主要な発声ボタンが見つけやすいようにする。

### iPhone縦画面【必須】

- **横画面と同一の文字順・配列・空欄位置で、全てのキーを同時に表示する**。
- 自動的な行列の並べ替え、横スクロール、ページ内の文字省略は不可。
- 文字とボタンが横向きより小さくなることは許容。表示できない場合は余白・補助UI・行間等を優先的に圧縮する。
- 小さいキーでも可能な範囲で押しやすさを追求し、実機評価が必要なリスクとして報告する。

### iPad・PC

- 同じ位置関係と機能を使い、画面サイズに合わせてキーを拡大する。
- マウス／キーボードの基本操作、タブ移動・フォーカス表示も確保する。

### 共通

- ノッチ・ホームインジケーターを `env(safe-area-inset-*)` 等で適切に避ける。
- 画面回転中に入力した文章・カーソル・ページ・選択した声が消えない。
- 意図しない文字選択、ズーム、二重入力、ページ全体の横スクロールを抑える。
- **スワイプ操作を文字タップと誤認しない**。タップしていない文字が入力されないよう、操作判定のテストを設ける。
- 向きはアプリ側で強制固定せず、端末の縦・横両方に対応する。

## 6. 文章入力・編集

- キーを押すと**現在のカーソル位置**にその文字を追加する。
- 上部に入力文章を大きく表示する。長文は折り返し、文章エリア内だけスクロールできる。
- 文章をタップしてカーソル位置を移動し、文章途中への挿入・修正が可能。
- `1文字削除` はカーソル直前の1文字を削除する（日本語の結合文字などを不自然に分断しないよう考慮）。
- `全文削除` は確認後に実行し、**元に戻す**で復元可能にする。
- 編集操作の `元に戻す`（Undo）を用意。必要なら `やり直す`（Redo）も設ける。
- スマートフォンで文章をタップしただけで標準ソフトキーボードが開き、文字盤が隠れる問題を避ける。カスタム文字盤とカーソル位置変更の両立を図る。
- 読み上げ後も文章は残る。スワイプ後・アプリ再起動後も入力中の内容を保持する。
- 画面初期値にモックアップの例文を固定表示しない。例文はプレースホルダーにとどめる。

### 保存方針

- 入力途中の**現在の文章・カーソル位置・必要な設定**を端末内に自動保存。
- ページ再読み込み・アプリ再起動後に復元できる。
- **会話履歴（過去の文章一覧）は初期設定で保存しない。** 「現在入力中の文章を復元すること」と「会話履歴を蓄積すること」は明確に分ける。
- 端末内の保存データが消される可能性があるため、必要なエラー処理を施す。

## 7. 日本語音声読み上げ【重要・オフライン優先】

このアプリは**音声入力（マイク認識）ではない**。**文字で入力した文章を、できるだけ自然な日本語音声で読み上げるアプリ**。

### 期待する動作

- 大きな「発声」ボタンをタップして、**文章全体をまとめて**読み上げる。
- ひらがな一文字ずつを独立して発声しない。
- 声は自然な抑揚・適切な間・聞き取りやすさを重視する。
- 同じ文章を繰り返し発声でき、終了後も文章を保持する。
- `停止` で途中の読み上げを停止できる。
- 再度発声する際に、前の読み上げをキャンセルするなどして重複再生を防ぐ。
- 空文字・空白だけの場合は無音にする。

### 実装方針

- まずブラウザーで利用できる **Web Speech API / SpeechSynthesis** を検討・実装する。
- `ja-JP` を適切に指定し、日本語音声候補を取得する。
- **端末内の音声（ローカル音声）を優先**し、可能なら `localService` を参照して利用者にわかる形で選択できるようにする。
- 声の候補、速度調節（ゆっくり／ふつう／速め等）、短い試聴、設定保存を備える。標準速度は聞き取りやすいものにする。
- 句読点や改行を考慮して、できる範囲で自然な間合いをつくる。ただし**本人の文章の意味や文面を勝手に書き換えない**。
- Web APIの音声について、**localService表示だけで実機オフライン利用を保証したと判断しない**。
- iPhone実機で**機内モード・Wi-Fiオフの両方を踏まえた実際の読み上げテスト**が必要。音声自体が未検証なら明示する。
- ローカル音声が使えない場合はその状態を表示し、**文章を無断で外部のオンラインTTSへ送信しない**。
- 自然さと完全オフラインの両立がWeb/PWAでは実現しきれない場合、制限・原因・iOSネイティブ方式等の代案を報告する。黙って要求を下げない。

今回、外部クラウドAI音声、有料API、バックエンドへ文章送信する機能は**追加しない**。

## 8. 「よく使う言葉」機能

- 利用者が自由に文章を登録・編集・削除できる。
- 現在の文章をお気に入りとして保存できる。
- 登録した言葉をタップすると**その文章を即座に発声**する。意図しない既存文章の上書きを避けるため、元の入力文章は保持する設計を優先する。
- 並び順を変更できる。
- 端末内に保存する。
- 編集・削除は通常の発声操作と区別する。

初期例（編集・削除可能）：

- はい
- いいえ
- ありがとうございます
- もういちどおねがいします
- すこしまってください
- てつだってください
- ちがいます
- わかりません

初期候補をたくさん詰め込んで文字盤の操作スペースを圧迫しない。お気に入り一覧は別のパネル／画面として開く方式でよい。

## 9. デザインとアクセシビリティ

- 正式アイコンに合う**温かいクリーム・白・コーラル・淡い黄色・緑・水色**を基調とする。
- 文字盤は**青文字＋白〜クリームのボタン**。入力文章は黒系統で大きく表示。
- 角丸、適切な余白、明瞭な押下状態。かわいすぎず、幅広い年齢が使える印象。
- 発声ボタンを最重要ボタンとして明確に区別する。削除操作との押し間違いを防ぐ。
- 色覚差に配慮し、色だけで意味を示さない。アイコン＋日本語ラベルを活用する。
- 可能な限りアクセシブルなラベル、フォーカス表示、スクリーンリーダー向けの説明を用意する。
- 設定画面は誤操作しにくい入口にする。通常の会話時の操作を邪魔しない。
- 不要な効果音、過剰なアニメーション、押すたびの音声再生は入れない。
- iPhone縦向きは文字盤10列固定を優先するため、一般的な推奨タップサイズを満たせない場合がある。隠したり勝手に配列を変えたりせず、リスクと評価方法を明示する。

## 10. PWA・オフライン・プライバシー

- iPhoneのSafariからホーム画面に追加して、アプリらしく起動できるPWAを作る。
- manifest、Service Worker、適切なアイコン、Apple touch icon、画面のメタタグ、キャッシュ更新を設定する。
- 初回オンライン読み込みとキャッシュ準備後、**ネットがなくても画面起動・文字入力・編集・お気に入り・設定が使える**こと。
- 外部CDNのフォント・ライブラリをオフライン動作の必須条件にしない。
- キャッシュ更新時に利用者の入力文章や登録言葉が消えないようにする。
- 基本機能はログイン不要。個人・学校・家庭の情報をサーバーへ送信しない。
- 会話本文をURL、アクセスログ、外部解析、エラー送信などに含めない。
- PWAのキャッシュと**オフライン音声の可否は独立に検証**する。

## 11. 実装品質・テスト項目

### 自動テストで確認すること

1. 清音の50マス、左から右の列順、2つの空欄位置、左端の「、」「。」が仕様どおり。
2. 濁音・半濁音25文字が直接入力でき、配列が仕様どおり。
3. 小文字・記号・空白・改行が入力できる。
4. ページ切り替えで文章・カーソル位置が保持される。
5. カーソル位置への挿入、1文字削除、全文削除確認、Undoが動く。
6. 発声処理が文章全体を受け取り、1文字ずつ発声しない。連続押し時に発声が重ならない。
7. お気に入り登録・編集・削除・即時発声が動作する。
8. 入力中の文章と設定が保存・復元され、不要な会話履歴は作られない。
9. 文字盤のスワイプ操作による**誤入力・二重入力を防げる**。
10. 画面サイズ変更・端末回転後もキー順が変わらない。

### ビルド／動作確認

- TypeScript型チェック、Lint（用意した場合）、テスト、プロダクションビルドを実施する。
- 利用可能ならモバイル相当の画面サイズでブラウザE2Eテスト、スクリーンショット検証を行う。
- 特に**iPhone横向き**で、記事全体が不要にスクロールせず全キー表示されるか確認する。
- **iPhone縦向き**でも同じ配列を全表示する。
- 文字キーのはみ出し、ノッチとの重なり、改行時の画面崩れ、PWAホーム画面アイコンを確認する。
- iPhone Safari実機、PWA起動、オフライン読み上げなど、この環境で試せない項目は**未検証**にしてユーザー向けの具体的確認手順を付ける。

### 受け入れ確認用の操作シナリオ

- 清音ページで「き」を押す → 3ページ目で「ょ」 → 清音ページで「う」 → 続けて「は」 → 濁音ページで「ぱ」を押すと、意図どおりの文字列ができる。
- 「きょうはたのしかた」を入力 → 文中の必要箇所にカーソル移動 → 「っ」を挿入して直せる。
- 「は・な・し・た・い」と入力 → 発声 → 同じ文章を再発声 → 文章が消えずに残る。
- 文章途中でiPhoneを縦横回転 → 清音・濁音等の配置が保持され、入力文章も残る。
- 文章を作ってアプリを閉じる → 再度開いて復元できる。
- 一度正常にオンライン起動しキャッシュ準備 → 通信を切って起動し文字操作ができる。音声は**実機テスト結果を別に**報告する。

## 最終目標

「こえのわ」は、伝えたいことがある利用者が、覚えた文字位置を頼りに一文字ずつ入力し、**自然で聞き取りやすい声で自分の意思を相手へ伝えられる**アプリです。

- **文字配列は絶対に勝手に変えない。**
- **主にiPhoneで使用。横・縦とも全体を一画面表示。**
- **清音／濁音・半濁音／小文字・記号の3ページ。**
- **文字タップは無音、文章全体を「発声」で読み上げる。**
- **通信なしで使える構成と、端末内日本語音声を優先。**
- **正式アイコンは添付画像をそのまま使用。**
